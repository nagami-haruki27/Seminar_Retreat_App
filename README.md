# 人力Semantle

研究室合宿のチーム対抗レク用アプリ。司会がお題を出し、各チームが出した単語とお題の「意味の近さ」を
埋め込みモデルのコサイン類似度で判定する。司会のPCをプロジェクターにつないで使う。
ネット接続なしで動く（モデルは事前にダウンロードしておく）。

## 1. セットアップ（合宿前に1回、ネットのある場所で）

Python 3.12 で動作確認。PowerShell か VS Code のターミナルで、このフォルダを開いて:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python scripts/download_models.py        # 既定の3モデル（約5GB、回線によって10〜30分）
```

`download_models.py` はモデルをダウンロードしたあと、基準語彙 100 語の埋め込みも計算してキャッシュに入れる。
途中で止まったら同じコマンドをもう一度実行すればよい（済んだ分は飛ばされる）。

- 軽量版だけで良ければ `python scripts/download_models.py --models ruri-v3-30m`
- 全モデルなら `--all`
- 「symlinks on Windows … Developer Mode」という警告が出るが無害（ディスクを少し多く使うだけ）

## 2. 起動

`run.bat` をダブルクリック、またはターミナルで:

```powershell
.venv\Scripts\activate
streamlit run app.py
```

ブラウザが開いて `http://localhost:8501` に **司会者用画面** が出る。これは手元の PC の画面に置く。
終了はターミナルで Ctrl+C。

### 画面は 2 つ

| 画面 | URL | 置き場所 | 内容 |
|---|---|---|---|
| 司会者用 | `http://localhost:8501/` | 手元の画面 | お題・単語の入力、投影の操作、全チームの結果と生の数値、基準単語の一覧、司会ツール |
| 投影用 | `http://localhost:8501/?view=screen` | プロジェクター | スライド 1 枚だけ。ボタンも入力欄も無い |

司会者用画面の「📺 投影用の画面を開く ↗」を押すと投影用が別タブで開く。そのタブをウィンドウとして切り離して
プロジェクター側の画面へ移し、**F11** で全画面にする（Windows の表示設定は「拡張」にしておく）。
投影用は司会者用の操作に 1 秒以内で追従する。入力中の単語や未発表の結果は投影用には出ない。

アプリは既定で **オフラインモード**（Hugging Face に接続しない）で動く。会場の Wi-Fi が不安定でも固まらない。

## 3. 合宿前のチェックリスト

- [ ] `python scripts/download_models.py --check` で 3 モデルとも `OK` が出る（ネットを切って試すとなお良い）
- [ ] `run.bat` で起動し、サイドバーの「モデルを読み込む」を押して読み込み時間を確認する（このPC では Ruri 310M が約 10 秒、Qwen3 が約 20 秒）
- [ ] 適当なチーム名でゲームを始め、お題「拡散モデル」で試し打ち（`data/topics.md` に例がある）
  - 反則の表示（お題と同じ単語を入れてみる）
  - 「次を発表 ▶」の演出、基準単語スライド、累計得点の更新
  - Undo、得点の手動修正
- [ ] プロジェクターにつないで投影用画面を全画面にし、後ろの席から文字が読めるか確認。サイドバーの「投影画面の文字の大きさ」で調整する
- [ ] ルール②を使うなら目標値を決めておく（補正A なら 0.4〜0.6 が遊びやすい。`docs/model_comparison.md` の表が参考になる）
- [ ] 前回の試し打ちの得点を消す: サイドバー「🆕 新しいゲームを始める」（古い記録は `save/` に日時付きで残る）
- [ ] `python -m pytest` が全部通る（任意）

## 4. 遊び方

1. 起動したらチーム数と名前を入れて「ゲーム開始」
2. サイドバーでルールとモデルを選ぶ（途中で変えても良い）
   - **ルール①**: お題に一番近い単語を出したチームの勝ち
   - **ルール②**: スコアが目標値（既定 0.5）に一番近いチームの勝ち
3. 司会がお題を入力して「📢 お題を投影」。投影用に「お題」スライドが出る（制限時間を設定していればタイマーも出る）
4. 各チームの単語をまとめて入力して「🎯 判定！」。投影用は「結果発表」スライドに切り替わる
   - 司会者用画面には、この時点で全チームの順位・スコアと「📚 基準単語との比較」が出る（未発表の行には 🙈 が付く）
5. 上の投影コントロールの「次を発表 ▶」で下位から 1 チームずつ発表（自動送りも可）。1位に3点、2位に2点、3位に1点
6. 発表が終わると「次へ」は「基準単語へ ▶」→「累計得点へ ▶」と進む
7. 「➡️ 次のラウンドへ」で入力画面に戻る（入力は空になり、投影は累計得点のまま）。入力画面の「結果をもう一度見る」で前回の結果に戻れる

### スライド（投影用画面）

| スライド | 内容 | 出るタイミング |
|---|---|---|
| タイトル | アプリ名とチーム名 | ゲーム開始時 |
| ルール説明 | 今の設定（ルール・得点・反則）から自動で作る | 「次へ」または直接選ぶ |
| お題 | 第 N 問、お題、タイマー | 「📢 お題を投影」 |
| 結果発表 | 下位から 1 チームずつ。未発表の行は「？？？」 | 「🎯 判定！」 |
| 基準単語 | 基準単語の最高スコアと上位 5 語。発表が済んでいれば 1 位の回答も並ぶ | 結果のあとの「次へ」 |
| 累計得点 | 発表が終わるまで、そのラウンドの得点は足さない | 基準単語のあとの「次へ」／次のラウンドへ |

司会者用画面の上にある投影コントロールで、「◀ 前へ」「次へ ▶」のほか、スライド名のボタンで好きなスライドへ直接飛べる。
「基準単語」を流れから外したいときは、サイドバーの「結果のあとに『基準単語』スライドを挟む」をオフにする（直接選べば出せる）。

### 基準単語の最高スコア

基準語彙 100 語（ふつうの単語）それぞれとお題のスコアを計算し、高い順に上位 10 語を記録している。
「ふつうの単語でもここまでは出る」という目安になり、チームの回答がそれを超えたかどうかが分かる。

- 司会者用: 結果画面の「📚 基準単語との比較」に、基準単語の最高スコア・チームの最高スコア・超えたチーム数と、上位 10 語の表（スコアと生の類似度）
- 投影用: 「基準単語」スライド
- 履歴の表にもラウンドごとの「基準単語の最高」が出る
- 方式B（パーセンタイル）では基準単語の最高は定義上 1.000 になるので、生の類似度の列を見る

### 反則

- お題と同じ単語、お題を含む単語（「拡散モデル」に対して「潜在拡散モデル」）は反則で 0 点
- 全角・半角、大文字・小文字、カタカナ・ひらがな、前後の空白の違いは吸収して判定する
- 漢字とかな（「猫」と「ねこ」）、英訳などは自動では判定できない。結果画面の「司会判断」でそのチームを反則にできる
- 「お題に含まれる単語」（「拡散モデル」→「拡散」）を反則にするかは設定で切り替え（既定: 反則にしない）

### 同順位

- 同じ単語を出したチームは同じスコア・同順位。1位が 2 チームなら両方 3 点で、次のチームは 3 位（1 点）

### スコアの補正

モデルによって類似度の分布が大きく違う（mE5 は無関係な単語でも 0.8 前後）。そのため補正したスコアを使える。
生の類似度は結果画面の「📊 グラフと詳しい数値」と履歴の表で見られる。

- **方式A（既定）**: 基準語彙 100 語とお題の平均類似度を 0、お題そのものを 1 とする線形変換。負の値も出る
- **方式B**: 基準語彙の中での順位（パーセンタイル）。お題に関係ある単語はほぼ 1.0 に張り付くので、同点のときは生の類似度で順位を決める
- **補正なし**: 生の類似度をそのまま使う

基準語彙は `data/reference_words.txt`（1 行 1 語、`#` でコメント）。編集したら `download_models.py` を再実行するとキャッシュが先に作られる。
お題と重なる語（お題「冬」に対する「冬」）はそのラウンドでは自動で除かれる。

### 司会ツール（サイドバー）

- 直前のラウンドの取り消し（Undo）。何回でもさかのぼれる
- 得点の手動修正（履歴に残り、個別に削除できる）
- チーム名の変更、チームの追加
- 制限時間タイマー（表示だけ。時間切れでも自動判定はしない）
- CSV のダウンロード（`save/results.csv` にも毎ラウンド自動で書き出す。Excel でそのまま開ける）

### 保存と再開

得点・履歴・設定は毎回 `save/game_state.json` に自動保存される。アプリを閉じても、起動し直せば続きから。
1 世代前のバックアップ（`.bak`）も残り、ファイルが壊れていればそちらから復元する。

## 5. モデル

| 設定名 | モデル | 特徴 |
|---|---|---|
| Ruri v3 310M（推奨） | `cl-nagoya/ruri-v3-310m` | 日本語特化。類似度の分布が広く、補正なしでも遊べる |
| Ruri v3 30M | `cl-nagoya/ruri-v3-30m` | 軽量版 |
| Qwen3-Embedding 0.6B | `Qwen/Qwen3-Embedding-0.6B` | 多言語。英語の指示文を付けて使う（モデルカードの推奨） |
| Qwen3-Embedding 0.6B（指示なし） | 同上 | 指示文なし。類似度の分布が広く、補正なしでも遊べる |
| multilingual-e5-large | `intfloat/multilingual-e5-large` | 類似度が 0.7〜1.0 に偏る。補正推奨 |
| multilingual-e5-base | `intfloat/multilingual-e5-base` | 軽量版 |

モデル間のスコア分布の違いは `python scripts/compare_models.py` で表にできる（`docs/model_comparison.md` に実行結果あり）。
実測（このPC、CPU）で分かったこと:

- 単語同士だと、どのモデルも生の類似度は 0.75〜0.95 に圧縮される。無関係な単語（お題「温泉」に「GPU」）でも Ruri で 0.83、mE5 で 0.80。
  **補正A をオンにすると**無関係語が 0 前後、「湯」「露天風呂」が 0.7 前後になり、見た目で分かるスコアになる
- Qwen3 は指示文なしのほうが分布が広い（無関係語の平均 0.45 前後）が、「締切」に「りんご」が高く出るなど、順位の納得感は Ruri のほうが高い
- 速度（初回のモデル読み込み後）: 新しい単語 1 語あたり Ruri 約 0.05 秒、mE5 約 0.03 秒、Qwen3 約 0.4 秒。4 チーム分なら Qwen3 でも 2 秒程度
- ルール②の目標値は、補正A で 0.4〜0.5 にすると「微妙に関係ある単語」（お題「温泉」に「合宿」「リラックス」= 0.1 前後、「旅館」= 0.48）を狙う遊びになる

## 6. 構成

```
app.py                      画面（Streamlit）。ロジックは持たない
semantle/
  normalize.py              表記ゆれの正規化・反則判定
  calibration.py            補正（方式A・B）
  judge.py                  順位付け・得点（純粋関数）
  state.py                  ゲーム状態、JSON 保存／復元、Undo、手動修正、CSV
  service.py                埋め込み → 補正 → 判定の流れ、基準単語のランキング
  live.py                   司会者用・投影用で共有する状態と、スライドの進行
  slides.py                 投影用スライドの HTML
  embeddings/
    base.py                 EmbeddingBackend の共通インターフェース
    registry.py             モデルID と接頭辞の定義
    local_st.py             sentence-transformers 実装
    cache.py                メモリ＋SQLite のキャッシュ
    fake.py                 テスト用モック
data/reference_words.txt    基準語彙
data/topics.md              お題の例
scripts/download_models.py  事前ダウンロード
scripts/compare_models.py   モデル比較
tests/                      pytest（ロジック）＋ AppTest（画面の通し）
save/                       自動保存（起動時に作られる）
cache/                      埋め込みキャッシュ
legacy/                     以前の試作
```

テスト: `python -m pytest`（モデルは読まない。1 分以内に終わる）

## 7. 困ったとき

| 症状 | 対処 |
|---|---|
| 「モデルを読み込めませんでした」 | ネットのある場所で `python scripts/download_models.py` を実行 |
| 判定が遅い | 軽量版（Ruri 30M）に切り替える。初回だけモデル読み込みに時間がかかるので、開始前に「モデルを読み込む」を押しておく |
| 画面が固まった／ブラウザを閉じてしまった | ブラウザで `http://localhost:8501` を開き直す。得点は保存されている |
| 投影用画面が更新されない／閉じてしまった | 司会者用画面の「📺 投影用の画面を開く ↗」で開き直す。今のスライドがそのまま出る |
| アプリを起動し直したら投影がタイトルに戻った | 映しているスライドは保存しない。投影コントロールで出したいスライドを選ぶ |
| アプリが落ちた | `run.bat` で起動し直す。続きから再開できる |
| 得点を間違えた | サイドバーの Undo か手動修正 |
| 前回の記録を消したい | サイドバー「新しいゲームを始める」 |
